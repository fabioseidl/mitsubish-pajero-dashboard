# `glass_display` — Waveshare ESP32-C6-LCD-1.47

A second speed-only client on a tiny 1.47" panel, intended to be read off the
glass. No touch on this board at all.

## Board

| Item | Detail |
|---|---|
| MCU | ESP32-C6 (RISC-V), 4 MB flash, **no PSRAM** |
| Panel | Onboard 1.47" ST7789 IPS, 172×320 native, used in landscape 320×172 |
| Touch | none |
| Backlight | GPIO 22, active-HIGH, LEDC PWM via `CYDDisplay` |
| Platform | pioarduino `platform-espressif32` 54.03.21-2 (the C6 needs Arduino core 3.x) |
| Libraries | `GFX Library for Arduino ^1.4.9`, `lvgl ^9.2.2` |

The C6 is the reason this project pins a different, community platform build from
the rest of the repo — `espressif32@6.9.0` (Arduino core 2.x) has no C6 support.
`ARDUINO_USB_MODE=1` + `ARDUINO_USB_CDC_ON_BOOT=1`: serial is the native USB port.

## Pins and panel geometry (`include/pin_config.h`)

| Signal | GPIO |
|---|---|
| LCD MOSI / SCLK / CS / DC / RST | 6 / 7 / 14 / 15 / 21 |
| Backlight | 22 |
| TF-card CS (unused) | 4 |

The ST7789 is a 240×320 controller and this 172-wide glass sits centred in that
window, so column data starts at `(240-172)/2 = 34` (`PANEL_COL_OFFSET`). Offsets
are given for rotation 0; the driver re-applies them for `SCREEN_ROTATION 1`
(landscape, LVGL sees 320×172).

The LCD **shares its SPI bus with the onboard TF-card slot**. The card is unused
and its CS is parked HIGH at init so it never drives MISO onto LCD traffic.

IPS glass → colour inversion is switched on.

## Rendering

- LVGL partial-render buffer of **40 rows** of RGB565. There is no PSRAM, so it
  sits in internal SRAM next to the WiFi stack — keep it small.
- `draw16bitRGBBitmap` emits RGB565 big-endian over SPI, which matches LVGL's
  native pixels on this little-endian MCU, so there is **no byte swap** in the flush.
- Optional windshield mirroring via the `GLASS_MIRROR_X` / `GLASS_MIRROR_Y` build
  flags (both `0` by default), applied in `flushCb` so LVGL always draws
  un-mirrored. The flush reflects the area's position and then the pixels inside
  it, one row at a time, so a partial area lands correctly on the far side. One
  reusable mirrored-row buffer is kept for this. As on `main_hud`: Y alone =
  mirrored *and* upside down; X and Y together = plain 180°.
- Font is Roboto Bold 56 px, digits and `-` only, generated by `lv_font_conv` from
  `ui/client_simple_hud/assets/Roboto-Bold.ttf`. Three digits span ~97 px.

## Behaviour

`GlassScreenController` keeps `speed_kmh_` and `online_` as volatiles written from
the ESP-NOW callback and read in `tick()`, which snapshots both at once (the
callback can land between two reads) and repaints only when the shown value
differs. Offline renders grey dashes, so a stale reading is never mistaken for a
live one. The label auto-sizes, so it is re-centred after every text change.
